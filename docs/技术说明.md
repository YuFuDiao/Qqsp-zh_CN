# Qqsp 1.9.0 汉化技术说明

本文是汉化过程的完整技术记录，对应仓库中的 `tools/` 与 `src/`。

## 一、原理：为什么基本不用改程序

Qqsp 启动时（`src/main.cpp`）：

1. 语言 ID 取自配置里 `application/language`，缺省用系统区域 `QLocale::system().name()`；
2. **先找程序目录**下的 `Qqsp.<语言ID>.qm`，找不到才回退到 exe 内嵌资源 `:/translations/`（内嵌只有 `en_US`、`ru_RU`）；
3. 「选项 → 语言」下拉框扫描程序目录里所有 `*.qm`，语言名 / ID 取自文件内 `__LANG__` 上下文的 `__LANGNAME__` / `__LANGID__`。

所以只要把一份 `Qqsp.zh_CN.qm` 放进程序目录即可被识别、选中、加载。程序本身只有那些**无法通过 .qm 翻译**的固定字符串才需要打补丁。

## 二、改动清单

| # | 位置 | 改动 |
|---|---|---|
| 1 | `Qqsp.zh_CN.qm`（新增，28 KB） | 简体中文语言包，**414 条词条 / 37 个上下文** |
| 2 | `Qqsp.exe` | 4 类固定字符串汉化，**共 434 字节、51 处**，代码逻辑未改 |
| 3 | `Qqsp.zh-CN.qm`（新增） | 语言包的连字符别名，与 `Qqsp.zh_CN.qm` 逐字节相同 |
| 4 | 配置里的 `language` | 统一为 `zh_CN`（原值为 `zh-CN` 或 `en_US` 时会导致界面回英文） |

## 三、汉化覆盖范围

**语言包（.qm）覆盖**：

* 主窗口全部菜单（任务 / 游戏 / 设置 / 帮助）、工具栏、面板标题（主描述、对象、动作、附加描述、输入区域、图像）、关于对话框；
* 选项对话框全部条目，含 Windows 下被隐藏的 `Use case insensitive paths`（此条官方 `.ts` 里都漏了，是从 exe 反汇编里补出来的）；
* **Qt 内置对话框**：文件选择框、字体 / 颜色对话框、消息框按钮（打开 / 取消 / 保存 / 是 / 否 / 重试…）。Qqsp 自己不加载 `qt_*.qm`，所以把 Qt 官方简中词条（外加官方 5.13 缺失的 `QPlatformTheme` 标准按钮表）合并进了同一个语言包——不额外留文件，语言列表也不会多出空项。

**exe 内固定字符串（无法用 .qm 翻译，已原地等长 / 等槽替换）**：

| 类别 | 示例 | 做法 |
|---|---|---|
| 窗口标题 | `Qt Quest Soft Player` → `QSP·小说播放器` | 20 字节槽位等长替换，长度常量 `0x14` 不变 |
| QSP 引擎错误描述 28 条 | `Division by zero!` → `除以零` | UTF-16 宽字符串，NUL 结尾、无长度常量，中文更短故安全 |
| 错误对话框格式串 4 条 | `Location: %1\nArea: %2…` → `位置: %1\n区域: %2\n行号: %3\n代码: %4\n描述: %5`；`on visit` → `访问时`；`on action` → `动作时` | 长度被编译成 `mov edx, imm32` 常量，已同步改写该立即数（共 8 处），且新长度不超过字面量所在对齐槽位 |

## 四、为什么不处理 WebEngine 右键菜单

`QspWebBox` 里写了 `setContextMenuPolicy(Qt::NoContextMenu)`，右键菜单被程序主动关闭，故不存在未汉化菜单（Qt 5.13 官方本来也没有这部分中文词条）。

## 五、仍未汉化

* **游戏剧情文本**——在 `.qsp` 文件内部，属于文本提取 / 回写，与软件本身无关；
* Oniguruma 正则库内部错误串、`std::exception`（`bad allocation` 等）——只在致命错误时出现，属程序内部诊断信息，未处理。

## 六、语言 ID 的坑（1.9.0 汉化失效的根因）

现象：双击 `Qqsp.exe`，界面回英文。

原因：`QTranslator::load()` 只会在给定名字后追加 `.qm`，并在分隔符 `_` / `.` 处逐级截短（`Qqsp.zh-CN` → `Qqsp.zh` → `Qqsp`），**永远不会把连字符换成下划线**。于是配置里的 `zh-CN` 找不到文件 `Qqsp.zh_CN.qm`，回退内嵌英文资源，全部回到英文。

| 项目 | 出问题时的值 | 是否正确 |
|---|---|---|
| 配置 `application/language` | `zh-CN`（连字符） | ✗ |
| 程序目录里的语言包 | `Qqsp.zh_CN.qm`（下划线） | — |
| 语言包内部 `__LANGID__` | `zh_CN` | — |
| 程序实际去找的文件 | `Qqsp.zh-CN.qm` → 不存在 | ✗ |

两处帮凶：

1. 缺省值就是 `QLocale::system().name()`，中文 Windows 上正是 `zh-CN`，所以只要配置里的值缺失或被改坏就会再次掉坑；
2. **按游戏目录**保存的 `qqsp.ini` 会在打开游戏时用它的 `language` 覆盖内存里的 ID（`mainwindow.cpp` 的 `LoadSettings`），关闭时再写回全局配置（`SaveSettings`）——一个坏值会自我保留并扩散。

**修法**：放进一份逐字节相同的 `Qqsp.zh-CN.qm`。这样 `zh-CN` 与 `zh_CN` 都能命中，配置再被写坏也不会回英文。副作用是语言下拉框会多出一条同名的「简体中文」（两条的 data 都是 `zh_CN`，选哪条都对）。

彻底不依赖系统区域设置的做法：在 exe 同级目录放一个 `custom.ini`，程序检测到它就改用便携模式，所有设置都读写该文件：

```ini
[application]
language=zh_CN
```

## 七、重新打包

```powershell
python tools\mk_zh.py                      # 生成 out\Qqsp.zh_CN.qm（自带回环校验）
python tools\ts2qm.py out\Qqsp.zh_CN.ts    # 从 .ts 编译语言包
python tools\patch_exe2.py                 # 从 original\Qqsp.exe 生成 out\Qqsp.exe（幂等）
```

`patch_exe2.py` 校验方式：每一步都断言「字面量唯一存在」、中文长度不超出槽位、`mov edx, imm32` 的旧值等于原长度，任何一条不满足就整体失败，不会写出半成品。

## 八、验证记录

* **语言包可复现**：`mk_zh.py` 从 `src/Qqsp.ru.qm` + Qt 词条生成 414 条，输出与仓库内 `out/Qqsp.zh_CN.qm` **逐字节相同**（SHA256 `97bdf0e8…`）。
* **exe 补丁可复现**：以 SHA256 `7ad434c3…` 的原始 exe 为输入，`patch_exe2.py` 输出 SHA256 `390ce5d3…`，与仓库内 `out/Qqsp.exe` **逐字节一致**。
* **补丁最小性**：汉化 exe 与原版逐字节对比，仅 434 字节、51 处不同；PE 头未变、文件长度未变（均 666624 字节）；8 处长度立即数改写后反汇编仍是 `mov edx, imm32` + `lea rcx, [rip+…]`。
* **生成器正确性**：本仓库的 `.qm` 写入器与官方 `lrelease` 输出逐字节一致（用官方 `Qqsp.ru.qm` 做回环比对）。
* **加载验证**：用真实 `Qt5Core.dll` 复现 `main.cpp` 的 `QTranslator::load` 调用，`translate()` 取回 `任务(&Q)`、`快速保存`、`查找范围：`、`基本颜色(&B)`、`取消` 等，全部正确（`tools/qtprobe.py`、`tools/qllocale.py`）。
* **完整性扫描**：把 exe 的 `.rdata` 字面量与 `translate()` 调用点全部与语言包比对，唯一遗漏（`Use case insensitive paths`）已补。
